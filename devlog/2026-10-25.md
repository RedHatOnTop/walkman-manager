## The first packages, from the public tree

- Built from the exported tree (53af3bd, private main ee0474d), not from this repository:
  `spectre-run.sh all` green (146 + 3 tests), then `bundle` for the deb, rpm and AppImage.
- Fresh Ubuntu 24.04 VM: `apt install ./…deb` took 64 s and 183 packages (WebKitGTK 4.1,
  GTK 3, Ubuntu's udev rule; adb and fastboot through recommends). Nothing missing under
  `ldd`; the app opened in Korean.
- Fresh Ubuntu 24.04 cloud image with only Mesa, EGL and Xvfb added: the AppImage stopped at
  start with `walkman-manager: error while loading shared libraries: libharfbuzz.so.0: cannot
  open shared object file: No such file or directory`. HarfBuzz is on the AppImage exclude
  list because every desktop has it; it was the only host library `ldd` found missing in the
  extracted image. With `libharfbuzz0b` installed the app opened, and without adb on the
  machine it showed the "no adb" notice with the platform-tools download. The README says the
  AppImage takes the desktop's graphics and font libraries.
- Fresh Fedora 44 VM: `dnf install ./…rpm` took 99 s. The rpm requires only
  `libgtk-3.so.0` and `libwebkit2gtk-4.1.so.0`; its recommends brought android-tools
  37.0.0 and the Studio's tools. Nothing missing under `ldd`, the Korean desktop entry in
  place, and the app opened in Korean.
- Two things seen on those runs, PR #21: the empty Players page was titled Devices while the
  sidebar says Players, and the connect hints drew their marks in the signal orange that
  `docs/design.md` keeps for sound playing now. Both fixed.

## A first look at Windows

- The owner asked whether a Windows build could be tried. Draft PR #22: an `icon.ico`, a
  workflow that builds the program and an NSIS installer on GitHub's Windows image, and
  `scripts/dev/winvm.sh`, an unattended Windows 11 evaluation VM (Korean) driven over ssh and
  QMP.
- The installer put the app in the user's profile in 6 s; it opened in Korean, fetched Google's
  Windows platform-tools after the licence, and started its adb. Library and Studio pages
  render. Workspace tests on Windows: 133 pass, 5 fail, all in Linux-only parts (the A50
  drive copy, the Studio's bash kits).
- Ported on the branch: the Windows platform-tools archive and `.exe` names, local-time backup
  stamps, free space before a pull. The window now shrinks into the work area when the screen
  is short, which Windows' taskbar showed at 1440x900 and a 1280x800 X display showed on
  Linux (GTK reports no outer size before the window is mapped).
- Not tried: a player over WinUSB (none was connected). Linux only for now: the A50 drive
  install, Studio builds, SensMe through Wine.
