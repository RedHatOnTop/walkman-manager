# 2026-10-15

## Start

Request: a desktop manager for the NW-A55 and NW-ZX507 ("Ultimate Walkman Manager"), with
recovery through MTKClient, a GUI custom-image builder over the porting projects, music sync
and customisation, designed from scratch rather than from any existing project's style.
The scoping brief that preceded it is `nw-a55/docs/walkman-manager-app-brief.md`.

Stack as the brief set it: a Rust core shared by a CLI and a Tauri 2 shell, React UI.

## Facts gathered before writing code

- Both units were on USB: 054c:0bc1 is the NW-A55 on stock 1.02 with ADB (mass storage +
  ADB interfaces, serial = adb serial), 054c:0cf2 the ZX507 on the Android 13 GSI (ADB only).
  A Waydroid adb target over TCP was also listed; the registry must ignore it.
- mtkclient's `brom_config.py` carries `0x8590` ("MT8590/MT7683/MT8521/MT7623", legacy DA,
  `mt8590_payload.bin`), so the A55's SoC is in its table.
- Sony's Help Guides (print PDFs for nwa50 and nwzx500) gave dimensions, display sizes,
  weights, the codec tables, and the "Parts and controls" figures. Porta-Fi's ZX507 review
  confirms the USB-C port and microSD tray are on the left side, controls on the right,
  both headphone jacks on top.
- The A55 shell has busybox 1.21 (`/sbin/busybox`), whose `df -k` gives exact sizes;
  toolbox `df` only prints rounded K/M/G. Its old adbd returns CRLF.
- The ZX507 vendor sets `ro.sony.swid` (04.00.P.4.06.00) too, so it cannot be used to tell
  Walkman OS from Android; `ro.hardware=icx` / `ro.product.model=HAGOROMO_MODEL` can.
- NVP node 007 ("mid") on the A55 read `08 00 00 21 "128G"`, not one of Rockbox's A50 model
  ids. Model inside a family is told apart by internal capacity instead, and the UI says so.

## Built

- `uwm-core`: profiles, USB classification, adb client, probe script + parsers, registry.
  Tests run against sanitised transcripts captured from both units with the same script.
- Tauri shell with hotplug-driven scanning and remembered players.
- UI: sidebar, device overview grid, device page with the annotated drawing, mode notices,
  settings. Checked in a browser against the fixtures in dark and light, Korean.

## Build loop

- First remote run: `aws-burst up --type c7i.xlarge` was refused, the IAM policy denies
  non-flex types ("explicit deny in an identity-based policy"). Default is now
  `m7i-flex.large`.
- Second run stopped at `cargo fmt --check`: rustfmt's default width is 100. Added
  `rustfmt.toml` (`max_width = 120`) and formatted locally (rustfmt only, no compile).
- Third run: clippy `collapsible_if` twice (let chains). Fourth: all tests in `profile` failed,
  `missing field storageGb` — `rename_all = "camelCase"` applied to deserialising the TOML
  too. It is now `rename_all(serialize = "camelCase")`.
- Fifth run never reached cargo: rsync `--delete` could not remove `app/src-tauri/gen`,
  which the container writes as root. That directory is generated and is now excluded
  from the sync and from git.
- Sixth: `tauri (v2.11.6) : @tauri-apps/api (v2.12.4)` version mismatch. The MSRV-aware
  resolver kept tauri at 2.11.6 because `rust-version` was 1.88 and tauri 2.12 needs
  1.90. `rust-version` is 1.90 now, the manifest asks for tauri 2.12 / tauri-build 2.7,
  and the container settles `Cargo.lock` with `cargo metadata` before the `--locked` steps.
- Seventh run green: fmt, clippy `-D warnings`, 16 tests, release `walkman-manager` and `uwm`.

## P1 check on the real players

`uwm devices` lists both players and drops the Waydroid TCP target. `uwm snapshot` on each
matches the shell: ZX507 Android 13 GSI, API 33, slot b, 100 % charging 4.17 V 37.5 °C,
`/data` 53.5 GB and the exFAT card 127.8 GB with 56.8 GB free; A55 Walkman OS 1.02,
98 % charging 4.09 V, internal FAT32 13.2 GB with 8.0 GB free, no card.

The release binary on a private Xvfb display (X11 backend, DMA-BUF renderer off) shows the
same numbers on the overview and on both device pages. Not checked yet: unplug and replug
(needs hands on the cables) and a live stream's rate (needs playback started on a player).

## P2: library and sync

- lofty 0.25.4 read from its source before use: `get_string` takes `ItemKey` by value,
  `read_from_path` returns `FileParseError`, MP4 tells ALAC from AAC only through
  `bit_depth` in the generic properties. ASF/WMA is not read at all; such files keep their
  file name as title.
- DSF/DFF: lofty has no DSD reader. The ID3v2 block both formats may carry is parsed by
  probing it as an MPEG file with `read_properties(false)`. The MPEG reader seeks back
  from the end for ID3v1/APE footers, so a short block is padded with zeros first.
- The listing script runs as is on both players (read-only): the ZX507 card, 6,518
  files, in 2.1 s; the A55's busybox 1.21 `find -exec … {} +` works.
- tauri 2.12's `register_uri_scheme_protocol` serves covers as `art://localhost/<key>`;
  the folder picker is `tauri-plugin-dialog` 2.8 called from Rust, so the page needs no
  plugin permission.
- Clippy at 1.99 also wants `is_multiple_of`, `RangeInclusive::contains` and
  `slice::from_ref`; three short check runs.
- Core tests: 36 pass, among them DSF and DFF headers with ID3 titles, cover thumbnails
  cached by content, a folder scan with a sidecar `.lrc`, a broken FLAC skipped with
  lofty's message, plan actions and FAT-safe destination names.

## Real-app check of P2 and two tag fixes

On the release binary with a private library of seven files pulled read-only from the
ZX507: covers come through `art://`, presence pips match, the ZX507 card lists 6,194
tracks / 65.0 GB. Two bugs showed: an MP3 whose ID3v1-era tags were CP949 read as
"ÀÌ³ë·¡" (Latin-1 mojibake), and an untagged folder was labelled "Various artists".
`repair_legacy` in `library/scan.rs` re-decodes such strings (gate: C1 control bytes or
two adjacent bytes ≥ 0xA1; Shift_JIS when the result has kana/kanji and no half-width
katakana, else EUC-KR/CP949 when it has Hangul). A Python model of the rule repaired six
Korean and two Japanese samples and left Björk, Café, Ægir, Sigur Rós, Mötley Crüe,
Beyoncé, Žižek and Ñandú alone. Albums now carry `compilation` (true only when tracks
name different artists), so a folder without tags says "Unknown artist".

## Redesign (v2)

The first UI read as an admin console: a grey sidebar, bordered boxes, 12 px grey
key/value rows, the player as a small wireframe. Rebuilt the shell, home, device page,
library and dialogs around players as lit objects: a CSS-3D render of each body to scale
with its live screen, one orange accent for live state and the primary action, large
figures, and tiles instead of hairline rows. `docs/design.md` describes the new rules.
The technical drawing stays as the device page's "Drawing" view. Mock covers are now
typographic sleeves in six print styles, so screenshots read like a record shelf.

Checked on the release binary (WebKitGTK on a private Xvfb, both players connected):

- The first build showed only the front of each player, tilted: without accelerated
  compositing WebKitGTK flattens `preserve-3d`, and the side and top faces collapse.
  Each face now carries the whole view transform (`perspective() rotateX() rotateY()`)
  itself; the side buttons and jacks show in WebKitGTK and in Chromium alike.
- A rescan still showed "ÀÌ³ë·¡": tracks whose size and mtime are unchanged are reused
  from the stored index, so the new decoding never ran. `INDEX_VERSION` is now 2 and
  `scan()` ignores an index of another version; after that the album reads "이노래".
- The A55 came back with no volumes and "NW-A50 Series" as its name: its storage was
  open on this computer as a USB drive (`/run/media/person/WALKMAN`), so the player had
  unmounted it. The storage and music tiles and the send dialog now say so.
